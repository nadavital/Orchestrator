# Installed App Visual Regression List

This list tracks the product-facing visual and interaction regressions found during installed-app dogfooding. It is separate from the broader Codex parity ledger: these are issues visible in the local Orchestrator app that should be judged by manual dogfood plus focused Electron smokes.

## Open Regressions

| Issue | Impact | Proposed fix | Proof needed |
| --- | --- | --- | --- |
| Settings pages still need cross-page dogfood | Providers and global dividers/controls are materially calmer now, but Appearance, Browser, Worktrees, Shortcuts, Personalization, and Data controls still need a full installed-app pass at normal window sizes. | Continue flattening dense controls into Codex-style section rows, reduce repeated borders, group advanced controls behind disclosure, and keep each page to one clear primary column. | Focused `--settings`, page-specific screenshots, and manual installed-app navigation across every settings page. |
| Traffic-light controls need installed-app pixel dogfood | Window chrome can only be fully judged in the real macOS window. | Check the installed app at narrow and wide widths after the safe-area/anchor change and adjust if native controls still read off. | Manual installed-app screenshot with native traffic lights visible. |
| Composer still needs installed-app taste dogfood | Automated screenshots now show a calmer resting state, but the real installed window should still be judged against Codex at normal working sizes. | Dogfood the installed app with empty, draft, attachment, permission-blocked, and side-chat states; continue hiding secondary state unless it is actionable. | Manual installed-app composer screenshots plus `--composer` smoke. |
| Side panel bottom-expanded compaction needs broader page dogfood | Plan and file-tab workflows now have screenshot-backed smoke proof, but Browser, Review, Git, and Environment still need installed-app taste checks at realistic bottom-panel heights. | Continue applying the bottom-expanded state to high-density panels only where content would otherwise become cramped. | `--browser`, `--environment`, `--diff-core`, and manual bottom-expanded screenshots for each remaining side-panel tab. |
| Git should not be a heavyweight dedicated tab for every workflow | Improved, but the full Git tab still needs installed-app taste dogfood to confirm it now feels like an advanced destination instead of a primary mode. | Continue moving common actions into Review/File/Workbench context actions; keep full Git only for explicit branch/status workflows. | `--environment`, `--diff-core`, and manual Git workflow dogfood. |
| Add project native dialog still needs installed-app dogfood | Native folder picker placement and long-running real-folder behavior cannot be fully proven in automated smoke. | Dogfood from `/Applications/Orchestrator.app`, verify the folder picker appears frontmost, and capture process/log evidence if a real folder still stalls. | Manual add-project run against a local repo plus visible status/error-state check. |
| App still has too many visible borders and sluggish animations in places | Design language feels heavier than Codex. | Continue removing nested card borders, prefer full-bleed panels/rows, and shorten slow transitions using shared motion tokens. | Manual contact sheet across sidebar, main chat, Workbench, Settings, side chat, and bottom panel. |

## Operating Rule

Do not treat the side-panel parity report as the visual regression list. The parity report is useful calibration, but this list should be updated only from installed-app dogfood, focused screenshots, or a user-visible workflow break.
